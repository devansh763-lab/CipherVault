How it works

Plaintext

The original, readable message before any encryption.

Ciphertext

The scrambled output of encryption. It should be unreadable without the key.

Encryption

Converting plaintext into ciphertext using an algorithm and a key.

Decryption

Turning ciphertext back into plaintext with the correct key.

Key

The secret value (a shift, keyword or alphabet) that controls the algorithm. A good system stays secure even if the algorithm is public.

Substitution cipher

Replaces each letter with another. Caesar, Substitution, Vigenère, Playfair and Affine work this way.

Transposition cipher

Keeps the letters but rearranges their positions. Rail Fence is an example.

Symmetric cryptography

The same secret key encrypts and decrypts. All ciphers here are symmetric.

Documentation

Overview and objectives

CipherVault is an educational tool for exploring classical ciphers. It aims to show how substitution and transposition work, how keys control encryption, and why these ciphers are broken today.

Built with HTML5, CSS3, vanilla JavaScript and the browser Clipboard API. No backend or database.

Architecture

User interface, then algorithm selection, then input validation, then the encryption/decryption engine (js/ciphers.js), then output display (js/app.js).

Limitation: classical ciphers fall to brute force and frequency analysis. Future scope: AES, RSA, SHA-256, frequency analysis and brute-force demos.
